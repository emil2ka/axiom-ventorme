## 2. Что блокирует конкурсную публикацию

1. **Официальный номер команды** (из списка организаторов). Пока неизвестен.
   Включение: скопировать `.env.example` → `.env`, заполнить:
   ```
   PUBLIC_VENTORME_MODE=competition
   PUBLIC_VENTORME_TEAM_ID=<номер из официального списка>
   ```
   Затем: `npm run build && npm run check:release` — проверка обязательна перед публикацией.
   Проверка уже протестирована на номере-образце `042` (OK) и отклоняет `017` как пример-заглушку.
2. **Публичное размещение.** Любой статический хостинг (Netlify / Vercel / Cloudflare Pages / GitHub Pages): загрузить содержимое `dist/`. Сайт полностью статический, серверная часть не нужна. Условие кейса: адрес открывается без аккаунта и в инкогнито.
3. **Проверка пути Ventorme** (см. §4): один участник проходит регистрацию как новичок и фиксирует факты.

## 4. Непроверенные факты (тексты честно нейтральны)

- Реальный путь `/register` и состав онбординга Ventorme.
- Доступность профтеста и его место после регистрации (поэтому кнопки называются «Зарегистрироваться в Ventorme», а не «Пройти профтест»).
- Условия бесплатного тарифа (никуда не написано «бесплатно»).
- Сохранение UTM при переходах внутри Ventorme (проверяется при кастдеве/регистрации).
- Официальный критерий «онбординг завершён» (по кейсу: регистрация + пройденный онбординг, вход через Google засчитывается).

## 5. Устройство проекта (для следующего разработчика)

- Стек: Astro 7 (static) + React 19 острова + motion; тесты vitest; скриншоты puppeteer-core (локальный Chromium из кэша ms-playwright).
- Единая точка URL регистрации: `src/config/campaign.ts`. Никогда не хардкодить ссылки в компонентах.
- Логика подборки: `src/lib/recommend.ts` — детерминированная, менять только с обновлением `tests/recommend.test.ts`.
- Контракты и карта файлов: `docs/contracts.md`, `docs/ownership.md`.
- Данные направлений и вопросов: `src/data/*.ts` — редакционные тексты, без зарплат/процентов/обещаний.
- События: `src/lib/events.ts` (свои, не блокируют переход); при желании подключить Яндекс.Метрику отдельным решением — не обязательна по кейсу.
- Полезные команды: `npm run dev`, `npm run build`, `npm run preview`, `npm test`, `npm run check:release`, `npm run shots`.
